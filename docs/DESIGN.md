# Design decisions and trade-offs

| Decision | Why | Trade-off |
|---|---|---|
| **Multi-stage retrieval**: BM25 + `bge-base-en-v1.5` dense vectors, fused with Reciprocal Rank Fusion, then a cross-encoder reranker (MS-MARCO MiniLM-L-12; `RERANK_MODEL=BAAI/bge-reranker-base` for more accuracy) | Each stage fixes the last one's weakness: BM25 keeps exact terms (SQL, Tableau), dense catches intent ("move into ML"), RRF merges them without tuning score scales, the cross-encoder reads query and course together for precise final order | Reranker adds ~100-300 ms per query on CPU and ~0.5 GB of models. Brute-force cosine won't scale to millions of courses; swap for FAISS/pgvector then. Every model stage is optional: missing models degrade to BM25 with a printed warning |
| **HyDE query expansion (Groq)**: the goal is rewritten as a hypothetical course description before dense embedding | Short questions embed poorly against long catalog text; a course-like query lands closer | One extra LLM call per new query (cached); skipped without a key |
| **Semantic skill matching**: learner skills and target skills are compared by embedding similarity, not strings | 'pandas' maps to data-analysis skills; a near-synonym of a target skill counts as already known (cosine >= 0.88) | Thresholds (`SKILL_SIM`, 0.8 / 0.88) are heuristics and should be tuned with `eval.py` |
| **Only trusted descriptions are indexed** (`description_status == ok`), otherwise the derived `summary` | The validation report shows 94 descriptions were mismatched and 221 missing; embedding them would poison retrieval | Less prose for those courses, so they rely more on skills/title |
| **Skills are the shared vocabulary** (catalog of 318) | Skill gap, path and prerequisite logic all operate on the same normalised terms | Learner's free text is mapped by whole-word match, so "python" maps to all python-* skills |
| **Groq is constrained, never authoritative**: it picks target skills only from candidates derived from retrieved courses, and writes explanations | Prevents hallucinated skills/courses; every course shown is a real catalog row | Two extra LLM calls (~1 s). With no key, everything degrades to rule-based output |
| **Path = greedy set cover + prerequisite injection + dependency-aware ordering** | Simple, explainable, near-optimal for small gaps; stays on the categories of the top matches to avoid drift | Not globally optimal; prerequisite edges are *inferred* from skill overlap (`prerequisites.csv`), so they are heuristic. Mutual (A<->B) edges are ignored |
| **Feedback -> +/-0.03 score per net vote (capped +/-3)** in `feedback.jsonl` | Personalisation with zero infra, immediately visible | Global, not per-user; a real system would need user ids and enough data to learn from |
| **Crawl4AI ingestion appends to a separate CSV** and re-indexes on `/scrape` | Original data stays untouched and the crawl is reversible (delete the file) | Full re-embed on each scrape (seconds at this size); scraped pages have no rating/duration and depend on LLM extraction quality |
| **Translated/duplicate listings dropped** (7 rows) | They created circular prerequisites and duplicate results | Loses non-English course access |
| **Pipeline as a LangGraph agent** (`graph.py`) with a typed state, conditional edges and bounded loops | Real decisions exist: weak results trigger query rewrite / filter relaxation, uncovered gap skills trigger a wider search, and each step is logged so the answer is explainable | Sequential graph adds little overhead but more moving parts than plain functions. Retry heuristics (<3 hits, >=4 categories in top 5) are simple and should be tuned; the agent relaxes user filters when needed and says so in the summary |
